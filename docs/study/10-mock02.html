함께 풀기 — 답과 이유 (Q10)

  • LGBMClassifier: 분류 문제이므로 Classifier로 끝나는 클래스를 씁니다.
  • verbose=-1: 지문이 학습 로그가 출력되지 않도록 -1을 지시했습니다. 1로 두면 로그가 출력됩니다.
  • predict(X_test_scaled): 학습 입력과 같은 스케일링된 평가 특성으로 예측합니다. 스케일링하지 않은 X_test는 오답입니다.
  • average='macro' 두 칸: 3클래스 이상에서는 average를 지정해야 하고, 문항은 macro를 지시했습니다. weighted는 오답입니다.
  • macro F1은 클래스별 F1을 같은 비중으로 평균하므로 소수 클래스에서 약하면 값이 내려갑니다.

함께 풀기 — 답과 이유 (Q14)

  • evaluate(X_test_scaled, y_test, verbose=0): 스케일링된 평가 데이터를 넣습니다.
  • np.argmax(pred, axis=1): pred는 (N, 3) 확률이고 행마다 가장 큰 위치를 고릅니다. 다중분류는 임계값 0.5를 쓰지 않습니다.
  • reindex(columns=X.columns, fill_value=0): 학습 때 12개 컬럼의 순서와 개수로 맞추고 없는 더미는 0입니다.
  • scaler.transform(new_df): 학습 때 만든 scaler를 재사용하며 fit하지 않습니다.
  • np.argmax(new_pred, axis=1)[0]: (1, 3) 확률에서 클래스 번호 하나를 얻습니다.
  • le.inverse_transform: 번호를 normal, overheat, wear 이름으로 되돌립니다.

정리

  • 문자열 타깃은 LabelEncoder로 정수 라벨을 만들고, le를 보관했다가 inverse_transform으로 이름을 복원합니다.
  • 다중분류는 Dense(n_classes, softmax), 정수 라벨이면 sparse_categorical_crossentropy입니다. 원-핫 라벨이면 categorical_crossentropy입니다.
  • 예측은 np.argmax(pred, axis=1)입니다. 임계값 0.5는 이진분류용입니다.
  • rul_days처럼 불량 이후에 산출되는 컬럼은 타깃 누수이므로 Q5에서 삭제합니다.
  • 클래스가 불균형하므로 stratify=y를 쓰고, accuracy와 함께 macro F1을 봅니다.
  • 신규 샘플은 reindex, scaler.transform, predict, argmax, inverse_transform 순서입니다.

  • 90분 타이머로 직접 풀고 점수와 틀린 문항을 기록해 옵니다.
  • 회귀에서는 출력층, 손실 함수, 평가지표, stratify, 예측 후처리가 어떻게 바뀔지 예상해 봅니다.
  • 오늘 정적 채점에서 의문이 생긴 문항은 다음 회차 시작 때 다시 확인합니다.

예상 질문과 답 (1)

Q1. 타깃을 원-핫으로 바꿔서 categorical_crossentropy를 써도 됩니까? 답: 출력층은 같고 손실 이름만 바뀌므로 짝만 맞으면 됩니다. 다만 이 회차의 Q6은 LabelEncoder를 지시하므로 정수 라벨 경로로 sparse_categorical_crossentropy를 씁니다.

Q2. LabelEncoder 번호가 왜 normal, wear, overheat 순서가 아닙니까? 답: 클래스 이름은 알파벳 순으로 번호가 붙어 0 = normal, 1 = overheat, 2 = wear가 됩니다. 순서를 외우지 말고 le.classes_를 출력해 확인하고, 이름 복원에는 le.inverse_transform을 씁니다.

Q3. Q5에서 이상치를 제거하지 않고 clip으로 값을 제한해도 됩니까? 답: 실무에서는 행을 보존하므로 clip도 많이 씁니다. 그러나 이 문항은 "제거"를 지시했으므로 불리언 조건으로 걸러 df에 재대입합니다. 문항이 요구한 방식을 따르는 것이 우선입니다.

예상 질문과 답 (2)

Q4. 딥러닝 accuracy(0.7886)가 랜덤포레스트(0.7937)보다 낮습니다. 잘못 만든 것입니까? 답: 아닙니다. 표 형태 데이터에서는 트리 계열이 딥러닝과 비슷하거나 더 좋은 경우가 흔합니다. 세 모델과 딥러닝의 accuracy가 0.77~0.79로 비슷한 범위입니다. 크게 낮을 때만 전처리와 모델 설정을 의심합니다.

Q5. Input(shape=(12,))처럼 숫자를 직접 써도 됩니까? 답: 값이 맞으면 동작하지만, 인코딩 결과가 바뀌면 맞지 않게 됩니다. X_train_scaled.shape[1]로 계산하면 안전하며, 문항도 특성 개수에 맞춰 지정하라고 요구합니다. 행 수를 넣는 shape[0]만 피하면 됩니다.

Q6. n_classes를 len(le.classes_) 대신 3으로 써도 됩니까? 답: 숫자 3을 직접 써도 정답입니다. len(le.classes_)는 데이터가 바뀌어도 통하는 코드라서 권장하는 형태입니다.
