#### M-3. `1,000행 ÷ batch_size 32 → 32 step`의 올림 근거가 본문에 없음
**담당: chapter-writer** · 위치: `ch03.md` 186행

> 데이터가 1,000행이고 `batch_size=32`라면 1 epoch은 32 step으로 이루어집니다.

`1000 / 32 = 31.25`이므로 32가 되려면 **올림(마지막 자투리 배치도 1 step)** 규칙이 필요한데, 본문은 이를 설명하지 않고 결과값만 제시한다. 산수가 맞지 않는다고 느낀 독자가 걸린다. 바로 뒤 "50 × 32 = 1,600번"도 같은 전제 위에 서 있다.

경계면 관점에서 더 문제인 것은, 이 규칙이 **본문이 아니라 `ch03_quiz.md` Q3 해설에서 처음 등장**한다는 점이다("마지막 자투리 배치도 1 step이므로 `ceil`로 올림합니다"). 다행히 Q3 지문이 "(마지막 배치도 1 step으로 셉니다)"라고 규칙을 자체 공급하고 Q3의 수치는 나누어떨어져 실질 피해는 없다.

**권고:** 186행에 "`1000 ÷ 32 = 31.25`이므로 마지막 자투리 묶음까지 세어 **올림하면 32 step**입니다" 한 절을 삽입. (커리큘럼상 `step = ceil(1000/32) = 32` 표기의 정본은 `ch05_epoch-batch` 도해이므로, Ch03에서는 수식 기호 없이 말로만 처리하는 것이 중복 회피에 유리하다.)

원소 1개짜리 배열에 numpy는 자릿수 정렬 패딩을 넣지 않는다. 값·정답·해설 논리는 전부 정확하고 오독 위험도 없지만, 파일 말미의 `verified:` 스탬프가 "전량 무오류 실행 / assert 통과"를 주장하는 데 반해 출력 전사가 손으로 다듬어진 흔적이다. 증적 신뢰도 차원에서 실제 출력으로 교체 권고.

#### L-2. 챕터 안에서 예시 신경망 형상이 4가지로 갈림
**담당: chapter-writer / diagram-designer (협의)** · 위치: 3.2 / 3.4 / 시험장 표준 코드

| 위치 | 형상 |
|------|------|
| `ch03_layer-stack` 도해 | 4 → 5 → 5 → 1 |
| 3.2 본문 코드 | 3 → 4 |
| `ch03_forward-backward` 도해 | 3 → 4 → 4 → 1 |
| 시험장 표준 코드 | 4 → 5 → 1 |

각각은 커리큘럼 스펙(도해)이나 설명 목적(코드)에 부합하므로 **오류가 아니다.** 다만 `ch03_forward-backward` 스펙의 "같은 신경망 위에 2단 화살표"를 읽고 3.2의 `ch03_layer-stack`과 동일 그림을 기대한 독자에게는 시각적 연결이 끊긴다. 개정 시 `ch03_forward-backward`를 4-5-5-1로 맞추면 두 도해가 "같은 신경망의 다른 관점"으로 읽혀 학습 효율이 오른다.

#### L-3. 시험 포인트 3의 Ch04/Ch05 역할 안내가 커리큘럼 분담과 어긋남
**담당: chapter-writer** · 위치: `ch03.md` 149행

> 출력층과 손실 함수의 짝은 Ch04와 Ch05에서 확정합니다.

커리큘럼 §2 의존 관계 주의사항은 **"손실 함수 선택 규칙의 정본 도해는 `ch05_loss-decision`이고 Ch04는 출력층 관점만 다루며 loss 표기 금지"** 로 못 박고 있다. 현재 문장은 "짝"의 담당을 Ch04·Ch05 공동으로 읽히게 해, Ch04에서 loss 표를 기대하게 만들 소지가 있다.

**권고:** "출력층은 Ch04에서, 출력층과 손실 함수의 짝은 Ch05에서 확정합니다"로 분리 표기.
