### C-1. §8.2 예상 출력 `입력 특성 수: 5` — 실측값은 `6` (담당: chapter-writer)

- **위치:** `ch08.md` 159행 (예상 출력 요지 블록)
- **실측:** 시드 고정(`np.random.seed(42)`, `rng = np.random.default_rng(42)`)이라 **결정적**으로 `입력 특성 수: 6`이 출력된다.
- **원인:** 4번 블록에서 `pd.get_dummies(df, columns=['contract_type'], dtype=int)`가 범주 3종(`month`/`one_year`/`two_year`)을 3컬럼으로 펼친다. 남는 수치 컬럼은 `tenure_months`·`monthly_fee`·`support_calls` 3개이므로 3 + 3 = **6**. 게재된 `5`는 원-핫 확장 전 컬럼 수(`df.shape`의 5)와 혼동한 값으로 보인다.
- **근거(실행 로그 발췌):**
  ```
  (1000, 5)          ← df.shape, 게재값과 일치
  입력 특성 수: 6     ← 게재값 5 와 불일치
  ```
- **조치:** 159행 `입력 특성 수: 5` → `입력 특성 수: 6`. 아울러 바로 위 `(1000, 5)`와 나란히 놓이면 독자가 "5개 컬럼 → 5개 특성"으로 오해하기 쉬우므로, 원-핫 3컬럼이 더해져 6이 된다는 한 줄 주석을 붙일 것을 권한다(이 챕터가 "인코딩은 분리 전"을 강조하는 만큼 교육 효과가 있다).

### C-2. §8.5 ①② 오류 재현 블록이 게재된 출력을 산출하지 못함 (담당: chapter-writer)

- **위치:** `ch08.md` 333~381행 (재현 코드 + 출력 요지)
- **문제:** 추출 코드가 `str(e).split('\n')[0][:110]` — **예외 메시지의 첫 줄**만 자른다. Keras 3.15에서 첫 줄에는 진단 정보가 없다.

  | | 게재된 출력(378~380행) | 실측 출력 |
  |---|---|---|
  | ① | `... expected shape=(None, 10), found shape=(None, 13) ...` | `Exception encountered when calling Sequential.call().` |
  | ② | `Received a label value of 2 which is outside the valid range of [0, 1) ...` | `Graph execution error:` |

- **파급:** 본문은 "**shape 숫자 두 개가 나란히 보이면 ①, `label value`가 보이면 ②**로 판별하면 됩니다"(374행)라고 지시하는데, 코드를 그대로 돌린 독자 화면에는 그 두 단서가 **한 글자도 나오지 않는다.** 절 전체의 학습 목표("메시지만 보고 원인과 조치를 판단")가 무력화된다. 예외 **타입**(`ValueError` / `InvalidArgumentError`)은 게재값과 일치하므로, 문제는 메시지 추출 로직에 국한된다.
- **실측 위치:** ② 의 `Received a label value of 2 ...` 는 총 41줄 중 **40번째 줄**에 있다. 본문 413행이 "오류 메시지의 **마지막 줄과 첫 줄**에 답이 있습니다"라고 옳게 서술하고 있는데도 코드는 첫 줄만 집는다 — 본문 서술과 코드가 서로 어긋난다.
- **조치:** `ch08_quiz.md` Q4(577행)가 **이미 올바른 관용구**를 쓰고 있으므로 본문을 그쪽에 맞추면 된다.
  ```python
  key = [ln for ln in str(e).split('\n') if 'label value' in ln or 'incompatible' in ln]
  print('  메시지 요지:', (key[0].strip() if key else str(e).split('\n')[0])[:110])
  ```
  본문과 문제집이 같은 관용구를 쓰게 되어 정합성도 함께 회복된다.

### H-1. `expected shape=(None, 10), found shape=(None, 13)`는 Keras 3 문구가 아니다 (담당: chapter-writer + diagram-designer)

- **위치 3곳:** `ch08.md` 326행(오류 표 대표 메시지) / 378행(출력 요지) / **`ch08_error-triage.svg`** (증상 ① 박스)
- **실측(Keras 3.15.0):**
  ```
  Input 0 with name 'None' of layer 'dense' is incompatible with the layer:
  expected axis -1 of input shape to have value 10, but received input with shape (None, 13)
  ```
  문자열 `expected shape=` 는 메시지 어디에도 나타나지 않는다(`'expected shape' in line` 매칭 0건). 게재 문구는 Keras 2 계열 표현이다.
- **판단:** 본문에 "버전에 따라 조금씩 다르지만"이라는 헤지가 있어 CRITICAL로는 올리지 않았으나, 교재 표준이 **Keras 2/3 양립**이고 검증 스택이 Keras 3인 만큼 3계열 문구를 정본으로 싣고 2계열을 병기하는 방향이 맞다. 다행히 "숫자 두 개(`10`과 `(None, 13)`)가 한 줄에 보인다"는 판별 heuristic 자체는 Keras 3에서도 성립하므로, 문구만 교체하면 교육 논리는 그대로 유지된다.
- **조치:** 세 곳을 Keras 3 문구로 교체(또는 `expected axis -1 ... value 10 ... shape (None, 13)` 축약형). SVG는 박스 폭 제약이 있으니 `expected axis -1 ... value 10` / `received input with shape (None, 13)` 2줄 분할을 권한다. C-2와 한 번에 처리할 것.

- **실측 대조:**
  ```
  ndarray → [0 0 0 0 1 0 2 1 2 0]
  Series  → 0    0
            1    0
            ...
            Name: churn, dtype: int64
  ```
- **조치:** "DataFrame에서 뽑은 타깃은 Series라 인덱스가 함께 찍힙니다. `y_train.values[:10]`로 보면 배열 형태로 확인됩니다" 한 줄 병기. 시험장에서 실제로 만나는 형태가 Series 쪽이므로 교육 가치가 있다.

### M-4. 교체 지점 개수가 "세 곳/세 줄"과 "네 곳"으로 오간다 (담당: chapter-writer)
