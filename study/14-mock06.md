## 오류 정정 Q5: 이상치 행과 컬럼 삭제 (2분)

주어진 코드:

```python
apple_temp = apple[apple['weight'] > 600]
apple_temp = apple_temp.drop('lot_id', axis=0)
```

모범 답안:

```python
apple_temp = apple[apple['weight_g'] <= 600]
```

## 결측치 처리 Q6: 중앙값으로 채우기 (2분)

```python
print(apple_temp.isnull().sum())      # sugar_brix 118, firmness_n 86, color_score 51

답안6 = 118

apple_na = apple_temp.fillna(apple_temp.median(numeric_only=True))
print(apple_na.isnull().sum().sum())  # 0
```

- `isnull().sum()`은 결측이면 1로 세어 컬럼별로 더합니다. 가장 많은 컬럼은 `sugar_brix`이고 개수는 118입니다. `답안6`은 컬럼 이름이 아니라 이 개수입니다.
- 평균 대신 중앙값을 쓰는 이유는 극단값의 영향을 덜 받기 때문입니다.
- `median(numeric_only=True)`는 컬럼 이름을 인덱스로 하는 Series입니다. `fillna`에 넘기면 같은 이름의 컬럼마다 해당 값으로 채웁니다.
- `sum().sum()`은 컬럼별 합을 다시 합한 총개수이며 0이 나와야 합니다.

자주 틀리는 답: `numeric_only=True` 누락(문자열 컬럼 때문에 오류), 결과를 `apple_na`에 저장하지 않음, `답안6`에 총 결측 수 255를 저장.

## 오류 정정 Q9: MinMaxScaler (4분)

주어진 코드:

```python
scaler = MinMaxScaler
X_train_s = scaler.fit(X_train)
X_valid_s = scaler.fit_transform(X_valid)
```

모범 답안:

```python
scaler = MinMaxScaler()
X_train_s = scaler.fit_transform(X_train)
X_valid_s = scaler.transform(X_valid)

# 학습 데이터 최댓값: 1.0
# 검증 데이터 최댓값: 1.02
답안9 = 1.02
```

고친 곳 세 가지:
1. `MinMaxScaler`에 괄호가 없으면 객체가 아니라 클래스 자체입니다. `MinMaxScaler()`로 만듭니다.
2. `fit`은 기준만 계산하고 scaler를 반환합니다. 변환된 배열이 필요하므로 학습 데이터에는 `fit_transform`입니다.
3. 검증 데이터에 `fit_transform`을 쓰면 검증 데이터로 기준을 새로 구합니다. 검증에는 `transform`만 씁니다.

---

## Q9와 답안9: 검증 최댓값이 1을 넘는 이유

- `MinMaxScaler`는 컬럼마다 `(값 - 최솟값) / (최댓값 - 최솟값)`을 계산해 0~1 범위로 만듭니다.
- 최솟값과 최댓값은 학습 데이터에서만 구합니다. 그래서 학습 데이터의 변환 결과 최댓값은 항상 1.0입니다.
- 검증 데이터에 학습 데이터에는 없던 큰 값이 있으면 같은 기준으로 변환해도 1을 넘을 수 있습니다. 이 데이터에서는 검증 최댓값이 1.02입니다.
- 검증 데이터에 `fit_transform`을 쓰면 검증 최댓값이 정확히 1.0이 됩니다. 이때는 출력이 예시(1.02)와 달라지므로 오류를 알아챌 수 있습니다.

자주 틀리는 답:
- 세 곳 가운데 3번만 고치면 `X_train_s`가 배열이 아니라 scaler라서 `np.max`에서 오류가 납니다.
- `답안9`에 학습 데이터의 최댓값 1.0을 적습니다. 저장할 값은 검증 데이터의 최댓값입니다.

## Q13: 딥러닝 다중분류 모델 (4분)

```python
le = LabelEncoder()
y_train_enc = to_categorical(le.fit_transform(y_train))
y_valid_enc = to_categorical(le.transform(y_valid))

model = Sequential([
    Input(shape=(X_train_s.shape[1],)),
    Dense(64, activation='relu'),
    Dropout(0.2),
    Dense(32, activation='relu'),
    Dense(3, activation='softmax')
])
model.compile(optimizer='adam', loss='categorical_crossentropy',
              metrics=['accuracy'])

es = EarlyStopping(monitor='val_loss', patience=5)
history = model.fit(X_train_s, y_train_enc, epochs=30, batch_size=32,
                    validation_data=(X_valid_s, y_valid_enc), callbacks=[es])
```

모범 답안 기준 마지막 epoch(30/30): accuracy 0.7942, val_accuracy 0.8148, val_loss 0.4535.

## Q13: 타깃 변환과 손실 함수의 짝

- `LabelEncoder`는 문자열 `'A'`, `'B'`, `'C'`를 알파벳 순서로 0, 1, 2로 바꿉니다.
- `to_categorical`은 정수를 `[1, 0, 0]`, `[0, 1, 0]`, `[0, 0, 1]` 같은 원-핫 벡터로 바꿉니다.
- 출력층은 클래스 수와 같은 3개 노드에 `softmax`를 써서 세 값을 합이 1인 확률로 만듭니다.
- 원-핫 타깃에는 `categorical_crossentropy`를 씁니다.

정수 라벨(`to_categorical`을 쓰지 않은 상태)을 그대로 쓰려면 손실을 `sparse_categorical_crossentropy`로 바꿉니다. 출력층은 같은 `Dense(3, softmax)`입니다. 두 방식을 섞으면 shape 오류가 납니다.

이 문항의 채점 규칙은 `sparse_categorical_crossentropy`, `'binary_crossentropy'`, `'sigmoid'`, 안내하지 않은 `validation_split`, `restore_best_weights`를 금지합니다.

검증 타깃에는 `fit_transform`이 아니라 `transform`을 씁니다. 인코더를 다시 만들지 않고 학습 데이터로 만든 규칙을 적용합니다.

## 모의고사 4, 5, 6회 비교

| 항목 | 4회 회귀 | 5회 이진분류 | 6회 다중분류 |
|---|---|---|---|
| 출력층 | `Dense(1, 'linear')` | `Dense(1, 'sigmoid')` | `Dense(3, 'softmax')` |
| 손실 함수 | `mse` | `binary_crossentropy` | `categorical_crossentropy` |
| metrics | `mae` | `accuracy` | `accuracy` |
| 타깃 인코딩 | 없음(연속값) | `LabelEncoder` 정수 0/1 | `LabelEncoder` 후 `to_categorical` 원-핫 |
| 정수 라벨을 쓸 때 | 해당 없음 | `binary_crossentropy` 그대로 | `sparse_categorical_crossentropy` |

- 4, 5, 6회 모두 `EarlyStopping(monitor='val_loss', patience=5)`와 `validation_data=` 형식입니다.
- 출력층 노드 수가 1에서 3으로 바뀌는 것은 클래스가 둘에서 셋이 되었기 때문입니다.
- 문제를 읽을 때 타깃이 연속값인지, 두 클래스인지, 세 클래스 이상인지부터 확인하면 이 표의 한 열이 정해집니다.

## 예상 질문과 답 (1)

**Q1.** Q5에서 왜 `<= 600`으로 쓰고 `> 600`으로 쓰지 않습니까?
답: 600을 초과하는 행을 삭제하는 작업이므로 남길 행은 600 이하입니다. `> 600`은 삭제할 행만 남겨 `apple_temp`가 30행이 됩니다. 정상 코드는 3000행에서 2970행이 됩니다.

**Q2.** Q9에서 검증 데이터의 최댓값이 1.02인 것은 잘못된 결과가 아닙니까?
답: 학습 데이터의 최솟값·최댓값 기준으로 변환했을 때 검증 데이터에 학습 데이터에 없던 큰 값이 있으면 1을 넘을 수 있습니다. 이 출력(1.02)이 `답안9`입니다. 검증에 `fit_transform`을 쓰면 1.0이 나오므로 그 경우가 오류입니다.

**Q3.** Q13에서 `to_categorical` 대신 정수 라벨을 쓰고 손실만 바꿔도 됩니까?
답: 코드로는 가능합니다. 정수 라벨이면 `sparse_categorical_crossentropy`를 씁니다. 다만 이 문항의 채점 규칙은 `to_categorical`과 `categorical_crossentropy`를 기대하고 `sparse_categorical_crossentropy`를 금지합니다.

## 예상 질문과 답 (2)

**Q4.** 이진분류인 5회에서는 `Dense(1, sigmoid)`인데 6회는 왜 `Dense(3, softmax)`입니까?
답: 5회는 클래스가 둘이라 한 개의 확률로 충분합니다. 6회는 세 등급이라 노드를 3개 두고 `softmax`로 합이 1인 확률 세 개를 냅니다. 이진분류용 `sigmoid`와 `binary_crossentropy`를 세 등급에 쓰지 않습니다.

**Q5.** Q6에서 `답안6`에 255를 적으면 왜 틀립니까?
답: 요구 사항은 결측치가 가장 많은 컬럼의 개수입니다. 컬럼별 개수는 `sugar_brix` 118, `firmness_n` 86, `color_score` 51이고 255는 세 컬럼의 합입니다.

**Q6.** Q13의 `EarlyStopping`에 `restore_best_weights`를 넣으면 안 됩니까?
답: 이 문항은 `monitor='val_loss'`, `patience=5`만 지정하고 "안내된 내용 외의 인자는 넣지 않습니다"라고 적었습니다. 채점 규칙도 `restore_best_weights`를 금지합니다. 문항이 지정한 인자만 씁니다.
