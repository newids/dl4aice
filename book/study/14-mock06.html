오류 정정 Q5: 이상치 행과 컬럼 삭제 (2분)

주어진 코드:

apple_temp = apple[apple['weight'] > 600]
apple_temp = apple_temp.drop('lot_id', axis=0)

모범 답안:

apple_temp = apple[apple['weight_g'] <= 600]
apple_temp = apple_temp.drop('lot_id', axis=1)

print(apple.shape, apple_temp.shape)   # (3000, 12) (2970, 11)

고친 곳: - 컬럼 이름은 weight가 아니라 weight_g입니다. - 600을 초과하는 행을 삭제하므로 남기는 조건은 <= 600입니다. > 600은 삭제할 행만 남깁니다. - 컬럼을 삭제하는 방향은 axis=1입니다. axis=0은 행 라벨로 해석됩니다.

행이 3000개에서 2970개로 30개 줄어든 것이 이상치 30건과 맞는지 출력으로 확인합니다.

결측치 처리 Q6: 중앙값으로 채우기 (2분)

print(apple_temp.isnull().sum())      # sugar_brix 118, firmness_n 86, color_score 51

답안6 = 118

apple_na = apple_temp.fillna(apple_temp.median(numeric_only=True))
print(apple_na.isnull().sum().sum())  # 0
  • isnull().sum()은 결측이면 1로 세어 컬럼별로 더합니다. 가장 많은 컬럼은 sugar_brix이고 개수는 118입니다. 답안6은 컬럼 이름이 아니라 이 개수입니다.
  • 평균 대신 중앙값을 쓰는 이유는 극단값의 영향을 덜 받기 때문입니다.
  • median(numeric_only=True)는 컬럼 이름을 인덱스로 하는 Series입니다. fillna에 넘기면 같은 이름의 컬럼마다 해당 값으로 채웁니다.
  • sum().sum()은 컬럼별 합을 다시 합한 총개수이며 0이 나와야 합니다.

자주 틀리는 답: numeric_only=True 누락(문자열 컬럼 때문에 오류), 결과를 apple_na에 저장하지 않음, 답안6에 총 결측 수 255를 저장.

오류 정정 Q9: MinMaxScaler (4분)

주어진 코드:

scaler = MinMaxScaler
X_train_s = scaler.fit(X_train)
X_valid_s = scaler.fit_transform(X_valid)

모범 답안:

scaler = MinMaxScaler()
X_train_s = scaler.fit_transform(X_train)
X_valid_s = scaler.transform(X_valid)

# 학습 데이터 최댓값: 1.0
# 검증 데이터 최댓값: 1.02
답안9 = 1.02

고친 곳 세 가지: 1. MinMaxScaler에 괄호가 없으면 객체가 아니라 클래스 자체입니다. MinMaxScaler()로 만듭니다. 2. fit은 기준만 계산하고 scaler를 반환합니다. 변환된 배열이 필요하므로 학습 데이터에는 fit_transform입니다. 3. 검증 데이터에 fit_transform을 쓰면 검증 데이터로 기준을 새로 구합니다. 검증에는 transform만 씁니다.

Q9와 답안9: 검증 최댓값이 1을 넘는 이유

  • MinMaxScaler는 컬럼마다 (값 - 최솟값) / (최댓값 - 최솟값)을 계산해 0~1 범위로 만듭니다.
  • 최솟값과 최댓값은 학습 데이터에서만 구합니다. 그래서 학습 데이터의 변환 결과 최댓값은 항상 1.0입니다.
  • 검증 데이터에 학습 데이터에는 없던 큰 값이 있으면 같은 기준으로 변환해도 1을 넘을 수 있습니다. 이 데이터에서는 검증 최댓값이 1.02입니다.
  • 검증 데이터에 fit_transform을 쓰면 검증 최댓값이 정확히 1.0이 됩니다. 이때는 출력이 예시(1.02)와 달라지므로 오류를 알아챌 수 있습니다.

자주 틀리는 답: - 세 곳 가운데 3번만 고치면 X_train_s가 배열이 아니라 scaler라서 np.max에서 오류가 납니다. - 답안9에 학습 데이터의 최댓값 1.0을 적습니다. 저장할 값은 검증 데이터의 최댓값입니다.

Q13: 딥러닝 다중분류 모델 (4분)

le = LabelEncoder()
y_train_enc = to_categorical(le.fit_transform(y_train))
y_valid_enc = to_categorical(le.transform(y_valid))

model = Sequential([
    Input(shape=(X_train_s.shape[1],)),
    Dense(64, activation='relu'),
    Dropout(0.2),
    Dense(32, activation='relu'),
    Dense(3, activation='softmax')
])
model.compile(optimizer='adam', loss='categorical_crossentropy',
              metrics=['accuracy'])

es = EarlyStopping(monitor='val_loss', patience=5)
history = model.fit(X_train_s, y_train_enc, epochs=30, batch_size=32,
                    validation_data=(X_valid_s, y_valid_enc), callbacks=[es])

모범 답안 기준 마지막 epoch(30/30): accuracy 0.7942, val_accuracy 0.8148, val_loss 0.4535.

Q13: 타깃 변환과 손실 함수의 짝

  • LabelEncoder는 문자열 'A', 'B', 'C'를 알파벳 순서로 0, 1, 2로 바꿉니다.
  • to_categorical은 정수를 [1, 0, 0], [0, 1, 0], [0, 0, 1] 같은 원-핫 벡터로 바꿉니다.
  • 출력층은 클래스 수와 같은 3개 노드에 softmax를 써서 세 값을 합이 1인 확률로 만듭니다.
  • 원-핫 타깃에는 categorical_crossentropy를 씁니다.

정수 라벨(to_categorical을 쓰지 않은 상태)을 그대로 쓰려면 손실을 sparse_categorical_crossentropy로 바꿉니다. 출력층은 같은 Dense(3, softmax)입니다. 두 방식을 섞으면 shape 오류가 납니다.

이 문항의 채점 규칙은 sparse_categorical_crossentropy, 'binary_crossentropy', 'sigmoid', 안내하지 않은 validation_split, restore_best_weights를 금지합니다.

검증 타깃에는 fit_transform이 아니라 transform을 씁니다. 인코더를 다시 만들지 않고 학습 데이터로 만든 규칙을 적용합니다.

  • 출력 첫 줄이 sugar_brix 0.377이고, 다음은 firmness_n 0.159, color_score 0.107입니다.
  • 이 문항은 이름(속성), 어느 모델인지, 정렬 방향이 한 번에 나옵니다.

함께 풀기 — 답과 이유 (Q12)

from sklearn.metrics import accuracy_score

dt_pred = dt_model.predict(X_valid)
rf_pred = rf_model.predict(X_valid)

dt_acc = accuracy_score(y_valid, dt_pred)
rf_acc = accuracy_score(y_valid, rf_pred)

답안12 = 'RandomForest'
  • 임포트할 이름은 accuracy가 아니라 accuracy_score입니다. 임포트 줄과 아래 호출 이름이 일치합니다.
  • 검증 정확도를 비교하므로 두 모델 모두 X_valid로 예측합니다. dt_model.predict(X_train)은 학습 데이터에 대한 예측입니다.
  • 정답과 비교하는 쪽도 y_valid입니다. rf_acc에 y_train을 넣으면 rf_pred(검증 데이터 예측)와 길이가 맞지 않습니다.
  • 정확도는 DecisionTree 0.6751, RandomForest 0.7609이므로 답안12는 'RandomForest'입니다.

정리

  • 오류 정정은 요구 목록을 읽은 뒤 이름, 인자, 데이터, 방향 순으로 확인하고, 고친 뒤 출력 예시와 비교합니다.
  • 수치형 결측치는 fillna(apple_temp.median(numeric_only=True))로 컬럼별 중앙값을 채웁니다. 답안6은 가장 많은 결측 개수 118입니다.
  • MinMaxScaler는 학습 데이터로 fit_transform, 검증 데이터는 transform입니다. 검증 최댓값이 1을 넘을 수 있어 답안9는 1.02입니다.
  • 다중분류 딥러닝은 LabelEncoder, to_categorical, Dense(3, softmax), categorical_crossentropy가 한 묶음입니다. 정수 라벨이면 sparse_categorical_crossentropy입니다.
  • 4, 5, 6회의 출력층·손실·지표·타깃 인코딩 차이를 표로 기억합니다.

예상 질문과 답 (1)

Q1. Q5에서 왜 <= 600으로 쓰고 > 600으로 쓰지 않습니까? 답: 600을 초과하는 행을 삭제하는 작업이므로 남길 행은 600 이하입니다. > 600은 삭제할 행만 남겨 apple_temp가 30행이 됩니다. 정상 코드는 3000행에서 2970행이 됩니다.

Q2. Q9에서 검증 데이터의 최댓값이 1.02인 것은 잘못된 결과가 아닙니까? 답: 학습 데이터의 최솟값·최댓값 기준으로 변환했을 때 검증 데이터에 학습 데이터에 없던 큰 값이 있으면 1을 넘을 수 있습니다. 이 출력(1.02)이 답안9입니다. 검증에 fit_transform을 쓰면 1.0이 나오므로 그 경우가 오류입니다.

Q3. Q13에서 to_categorical 대신 정수 라벨을 쓰고 손실만 바꿔도 됩니까? 답: 코드로는 가능합니다. 정수 라벨이면 sparse_categorical_crossentropy를 씁니다. 다만 이 문항의 채점 규칙은 to_categorical과 categorical_crossentropy를 기대하고 sparse_categorical_crossentropy를 금지합니다.

예상 질문과 답 (2)

Q4. 이진분류인 5회에서는 Dense(1, sigmoid)인데 6회는 왜 Dense(3, softmax)입니까? 답: 5회는 클래스가 둘이라 한 개의 확률로 충분합니다. 6회는 세 등급이라 노드를 3개 두고 softmax로 합이 1인 확률 세 개를 냅니다. 이진분류용 sigmoid와 binary_crossentropy를 세 등급에 쓰지 않습니다.

Q5. Q6에서 답안6에 255를 적으면 왜 틀립니까? 답: 요구 사항은 결측치가 가장 많은 컬럼의 개수입니다. 컬럼별 개수는 sugar_brix 118, firmness_n 86, color_score 51이고 255는 세 컬럼의 합입니다.

Q6. Q13의 EarlyStopping에 restore_best_weights를 넣으면 안 됩니까? 답: 이 문항은 monitor='val_loss', patience=5만 지정하고 "안내된 내용 외의 인자는 넣지 않습니다"라고 적었습니다. 채점 규칙도 restore_best_weights를 금지합니다. 문항이 지정한 인자만 씁니다.
