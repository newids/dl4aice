# 챕터 집필 가이드

## 도해 우선 원칙 (이 교재의 정체성)

이 교재의 요구사항은 "도해 위주의 설명"이다. 글은 도해를 보조한다.

- 새 개념 도입 순서: **도해 → 한 줄 요약 → 짧은 설명 → 코드**. 글부터 시작하지 않는다.
- 도해 없이 3문단 이상 이어지면 구조를 다시 짠다. 문단을 줄이거나 도해를 추가한다.
- 챕터당 도해 최소 4개를 목표로 한다. 비교(before/after), 흐름(파이프라인), 구조(모델), 판단(loss 선택 분기) 유형을 섞는다.
- 도해 플레이스홀더 형식 — 세 필드는 `{id} | {캡션} | {제작 지시}`:
  - **id**: `ch{NN}_{slug}` 형식. diagram-designer의 파일명·ebook-builder의 매칭 키가 된다
  - **캡션**: e-book에서 `<figcaption>`으로 독자에게 그대로 노출된다 (완성된 한국어 명사구로)
  - **제작 지시**: diagram-designer에게 전달되는 구도 묘사 (독자에게 노출 안 됨)

```html
<!-- DIAGRAM: ch03_dense-layer | Dense 레이어의 구조 | 입력 3개 노드가 출력 2개 노드에 완전연결되고 각 연결에 가중치 w, 노드에 편향 b가 표시된 구조도 -->
```

## 문체 규칙

- **광고 카피식 문구를 쓰지 않는다.** "도해로 익히고 코드로 끝낸다", "순서가 곧 점수다", "위치가 전부입니다"처럼 대구를 맞춘 구호, 단정적인 캐치프레이즈, 과장된 수식은 한국어 화자가 평소 쓰지 않는 옛 광고 말투다. 제목·부제·소제목·UI 문구·해설 어디에도 쓰지 않는다. 무엇을 다루는지 그대로 적는 평범한 설명문으로 쓴다(예: "분리한 뒤에 스케일링한다", "어디에 놓는가").

- 한국어 경어체 서술("~합니다")로 통일한다. 수험생 눈높이: 전문용어 첫 등장 시 반드시 한 줄 정의를 단다.
- "쉽죠?", "간단합니다" 같은 난이도 단정 표현 금지 — 독자가 어려우면 소외감을 준다.
- 자주 틀리는 지점은 `> ⚠️ **시험 포인트**` 인용 블록으로 강조한다. 챕터당 2~4개.
- 영문 용어는 첫 등장 시 "활성화 함수(activation function)" 형태로 병기하고 이후 한국어만 쓴다. 단 API 명칭(Dense, relu)은 코드 표기 유지.

## 코드 예제 규칙

- 모든 코드는 실행 가능한 완결형으로 작성한다 (import 포함). 실행 안 해본 코드를 싣지 않는다.
- **검증 증적 필수:** 챕터의 코드 블록을 실행한 뒤 챕터 파일 하단에 `<!-- verified: {날짜} {환경 요약} {결과 요지} -->` 주석을 남긴다. 증적이 없으면 tech-reviewer가 미검증으로 간주한다.
- AICE 환경 기준: TensorFlow 2.x Keras, pandas, sklearn. `tf.keras` 경로로 통일한다. Keras 버전 양립 패턴(`aice-domain` 스킬의 "코드 패턴 표준" 절)을 따른다.
- 재현성: 예제 데이터는 sklearn 내장 데이터셋 또는 코드로 생성하는 합성 데이터만 사용한다 (외부 파일 다운로드 금지).
- 코드 블록 위에 "무엇을 하는 코드인지" 한 줄, 아래에 예상 출력 요지를 적는다.
