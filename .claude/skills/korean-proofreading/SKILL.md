# 한국어 교정 기준

이 프로젝트의 글은 **수험생이 한 번 읽고 바로 이해하는 설명문**이어야 한다. 읽는 사람이 "이게 무슨 뜻이지?" 하고 멈추게 만드는 표현은 모두 고친다. 판단 기준은 하나다: **한국어를 모국어로 쓰는 사람이 동료에게 설명할 때 실제로 이렇게 말하는가.**

## 1. 고쳐야 하는 것

### 1.1 뜻이 흐려지는 은유·비유 (가장 중요)

기술 내용을 비유로 바꿔 말하면 읽는 사람은 비유를 다시 원래 뜻으로 풀어야 한다. 풀이가 따라붙지 않는 비유는 지우고 **실제로 일어나는 일을 그대로** 적는다.

| 고칠 표현 | 문제 | 고친 예 |
|---|---|---|
| 뉴런은 근거를 저울질해서 점수를 만듭니다 | 저울질이 어떤 계산인지 알 수 없다 | 뉴런은 입력마다 가중치를 곱해 모두 더합니다 |
| sigmoid가 값을 0과 1 사이로 누릅니다 | "누른다"가 무슨 연산인지 모호하다 | sigmoid는 값을 0과 1 사이의 값으로 바꿉니다 |
| 이 근거 조합이 해당할 때만 신호를 보냅니다 | 조합·해당·신호가 각각 무엇인지 없다 | 점수가 양수일 때만 그 값을 다음 층에 넘깁니다 |
| 과적합은 외운 것과 이해한 것의 차이입니다 | 비유가 정의를 대신한다 | 과적합은 학습 데이터에서는 잘 맞고 새 데이터에서는 잘 맞지 않는 상태입니다 |
| 오류 응급처치 | 의료 비유 | 오류 대처 방법 |
| 네 줄만 갈아 끼우면 됩니다 | 부품 비유, 과장 | 고쳐 쓰는 곳은 네 줄입니다 |
| 데이터가 흘러간다, 층을 통과한다 | 관용적으로 굳은 표현 | **그대로 둔다** (아래 1.1의 예외) |

- **남겨도 되는 비유:** 그 분야에서 용어처럼 굳은 표현(순전파·역전파의 "전파", 데이터 "누수", 모델을 "학습시키다", 층을 "쌓다", 값이 "흐르다")과, **바로 뒤에 실제 뜻을 풀어 준** 비유. 비유를 남길 때는 같은 문장이나 다음 문장에 실제 계산이나 동작이 적혀 있어야 한다.
- 사람이 아닌 것에 감정·의도를 주는 표현을 고친다: "모델이 두려워한다", "뉴런이 판단한다", "optimizer가 고민한다" → 실제 동작으로.

### 1.2 광고 카피식 문구

대구를 맞춘 구호, 단정적인 캐치프레이즈, 과장된 수식. `CLAUDE.md`의 문구 금지 규칙과 같다.

- "도해로 익히고 코드로 끝낸다", "순서가 곧 점수다", "위치가 전부입니다", "이 표 한 장이면 절반이 해결됩니다", "~의 모든 것", "단 세 줄", "핵심만 쏙쏙", "완벽 정리"
- "유일한 방법", "반드시 합격", "무조건", "절대" 같은 근거 없는 단정. 단, 실제로 예외가 없는 기술 사실("새 입력에는 `fit`을 쓰지 않습니다")은 그대로 둔다.

### 1.3 번역투와 어색한 문장

| 고칠 표현 | 고친 예 |
|---|---|
| ~에 의해 결정됩니다 | ~가 정합니다 / ~에 따라 달라집니다 |
| ~하는 것이 가능합니다 | ~할 수 있습니다 |
| ~를 가집니다 / ~를 갖습니다 (have 직역) | ~가 있습니다 / ~입니다 |
| ~에 있어서, ~에 대하여 (남용) | ~에서, ~을 |
| ~되어집니다, ~보여집니다 (이중 피동) | ~됩니다, ~보입니다 |
| 필요로 합니다 | 필요합니다 |
| ~함에 있어 중요한 것은 | ~할 때는 |
| 그것은, 이것은 (대명사 남용) | 가리키는 말을 다시 쓴다 |
| A의 B의 C (조사 '의' 연쇄) | 풀어 쓴다 |
| 수많은 ~들 (불필요한 복수 '들') | '들'을 뺀다 |
| ~를 통해 (남용) | ~로, ~해서 |
| 명사만 늘어놓은 문장 ("가중치 갱신 수행") | 서술어를 살린다 ("가중치를 고칩니다") |

### 1.4 뜻이 통하지 않는 낱말

- 지어낸 말, 줄임말, 뜻이 다른 한자어: "근거 조합", "정본", "판독"(→ 읽기), "투입"(→ 넣기), "수행"(→ 하다), "상이하다"(→ 다르다), "기출 답안"(이 교재의 문제는 기출이 아니다 → 모범 답안)
- 영어를 그대로 옮긴 말: "퍼포먼스가 나온다" → "성능이 나온다". 단, 코드와 API 이름, 이 교재가 표기를 고정한 용어(`_workspace/01_curriculum.md` §6 "용어·표기 통일 규칙")는 바꾸지 않는다.
- 한 문서 안에서 같은 것을 다른 말로 부르는 경우는 하나로 통일한다.

### 1.5 문장 다듬기

- 주어와 서술어, 목적어와 서술어가 맞지 않는 문장
- 한 문장에 내용이 셋 이상 들어간 문장은 나눈다
- 조사 오류, 맞춤법, 띄어쓰기, 외래어 표기
- 문체: 본문과 해설은 "~합니다" 경어체. 소제목과 표는 문서가 이미 쓰는 문체를 따른다.
- 줄표(—)로 끼워 넣은 말, "A가 아니라 B입니다" 식의 대비, 콜론 뒤에 답을 터뜨리는 문장은 평서문으로 푼다. 단, 제목의 "주제 — 설명" 형식은 이 교재의 조판 규칙이므로 유지한다.

## 2. 고치지 않는 것

- **코드:** 코드 블록, 인라인 코드(백틱 안), 변수명, 함수명, 인자 값, 출력 결과, 에러 메시지 원문
- **숫자와 사실:** 수치, 실행 결과, 기술적 주장의 내용. 표현만 고치고 뜻은 바꾸지 않는다. 내용이 틀렸다고 판단되면 고치지 말고 보고한다.
- **구조:** frontmatter, `<!-- DIAGRAM: ... -->`·`<!-- EXAM: ... -->`·`<!-- WIDGET: ... -->` 자리표시, `<!-- verified: ... -->` 주석, JSON의 키와 구조, HTML의 태그·id·class
- **`#`, `##` 제목 줄:** 제목이 바뀌면 페이지 주소(앵커)가 바뀐다. 직접 고치지 말고 수정 제안으로 보고한다. `###` 이하는 고쳐도 된다.
- **채점에 쓰이는 값:** `validation_rules`의 `type`, `callee`, `value`, `pattern`, `params` 등. `label`과 `hint`의 문장은 고친다.
- **이미 자연스러운 문장:** 고칠 이유를 한 줄로 말할 수 없으면 그대로 둔다. 취향으로 바꾸지 않는다.
- **도해(SVG):** 이 프로젝트의 도해 46개는 보존 대상이다.

## 3. 절차

1. 맡은 파일을 처음부터 끝까지 읽는다. 훑어보고 눈에 띄는 것만 고치지 않는다.
2. 문장마다 §1의 다섯 가지를 차례로 본다. 고칠 때는 **앞뒤 문장과 이어 읽어도 자연스러운지** 확인한다.
3. 고친 곳은 기록한다: 파일, 위치, 이전 문장, 고친 문장, 이유(§1의 어느 항목인지).
4. 고친 뒤 형식이 깨지지 않았는지 확인한다(마크다운 표와 코드 펜스, JSON 파싱, HTML 태그 짝).
5. 판단이 서지 않는 곳, 내용 자체가 의심스러운 곳, 제목 수정 제안은 고치지 않고 따로 보고한다.

## 4. 보고 형식

```markdown
## 요약
- 읽은 범위: (전부 읽었는지, 일부만 읽었다면 어디를)
- 고친 곳: N건 (은유·비유 n / 광고 문구 n / 번역투 n / 낱말 n / 문장 n)

## 고친 곳

| 파일 | 현재 제목 | 제안 | 이유 |

## 판단 보류·내용 의심
```
