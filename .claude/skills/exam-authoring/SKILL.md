# 출제·해설 규격

## 법적·윤리 원칙

기출 문제 원문은 비공개 저작물이다. 절대 복제하지 않는다.
공개된 출제 범위·유형(`aice-domain` 스킬 참조)에 기반한 **기출 변형 문제**를 만들고,
교재 문제 섹션 서두에 "본 문제는 공개된 출제 기준에 따른 유형 연습 문제입니다" 문구를 넣는다.

## 문제 유형 2종

### 1. 챕터 확인 문제 (`ch{NN}_quiz.md`) — 챕터당 4~6문항
- 객관식 2~3개 (개념 판별: "이진분류 출력층으로 옳은 것은?")
- 코드 빈칸 채우기 1~2개 (`model.add(Dense(1, activation='____'))`)
- 코드 오류 찾기 1개 (수험생이 실제로 자주 내는 오류를 심는다: loss-활성화 불일치, input_shape 누락, 스케일링 전 fit 등)

### 2. 실전 모의고사 (`mock_exam_{N}.md`) — 실기 시험 형식 재현
- 하나의 데이터셋 시나리오로 10~14단계 연속 문항 (탐색 → 전처리 → ML → DL → 평가)
- 실제 시험처럼 지시형으로: "X_train, X_test로 7:3 분리하시오. random_state=42를 사용하시오."
- 데이터는 코드로 생성하는 합성 데이터 (생성 코드를 문제지에 포함 — 독자가 로컬에서 풀 수 있어야 한다)
- 배점과 예상 소요 시간 명시

## 파일 구조 (문제부/해설부 분리)

```markdown
# {제목}
> 본 문제는 공개된 출제 기준에 따른 유형 연습 문제입니다.

## 문제
### Q1. ...
## 해답 및 해설      ← e-book에서 접힘 처리되는 경계. 반드시 이 헤딩명 사용
### Q1 해답
```

## 해설 3단 구성 (정답 나열 금지)

각 해설은 반드시 세 부분을 갖춘다:

1. **정답 코드** — 실행 검증된 코드 (아래 검증 절차 필수)
2. **왜 이렇게 푸는가** — 함수·파라미터 선택 이유. "sigmoid를 쓰는 이유는 출력을 0~1 확률로 만들기 위해서"처럼 판단 근거를 설명한다. 이유를 알아야 변형 문제에 대응한다.
3. **자주 틀리는 지점** — 감점 패턴 1~2개. 예: "`sparse_categorical_crossentropy`인데 라벨을 원-핫 인코딩하면 shape 오류"

## 해답 코드 검증 절차 (필수)

1. 문제의 데이터 생성 코드 + 해답 코드를 하나의 스크립트로 합쳐 Bash로 실행한다.
2. 오류 없이 끝나고 기대 출력(정확도 범위 등)이 나오는지 확인한다.
3. 딥러닝 학습은 `epochs`를 낮춰 검증하되, 문제지의 지시 값은 원래대로 둔다.
4. 실행 로그 요지를 파일 하단 `<!-- verified: {날짜} {결과 요약} -->` 주석으로 남긴다.

## 난이도 배분

- 확인 문제: 기본 70% / 응용 30%
- 모의고사: 실제 시험 체감 난이도로. 전처리·모델링 단계에서 이전 단계 결과를 이어받는 의존 구조를 유지한다 (실제 시험의 핵심 어려움).
